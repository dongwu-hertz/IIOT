01  项目目标与设计原则
1.1 目标
将事件中心从“记录查询页面”转变为“处置工作台（Operational Workspace）”。
让用户在一个页面内完成：筛选、识别严重度、查看证据、确认、分派、调查、关联、关闭。
形成跨产品统一体验：Acoustic / Thermal / DAS / DTS / DGA / Pipeline / Transformer 共用同一套事件模型和组件。
支持后续 AI：事件分类、置信度、重复告警聚合、跨传感器事件关联、Incident 建议。
1.2 设计原则
原则
要求

Evidence First
工业用户首先要知道“为什么系统认为这里有问题”。证据比装饰更重要。

Action Oriented
每一条告警必须有明确下一步：Acknowledge / Assign / Investigate / Resolve。

Calm by Default
页面保持白/灰主视觉；严重度只用于局部语义提示，避免满屏红黄。

Progressive Disclosure
列表只显示判断所需信息；深层字段放 Detail Drawer / Tabs。

One System, Many Sensors
不同检测产品在 Evidence 内容上变化，但导航、状态、筛选、处置流程统一。

禁止做法
不要把所有检测结果都直接称为 Alarm；不要把重复触发显示成数十条独立告警；不要把告警详情做成必须离开列表的全页跳转；不要用大量高饱和色或大面积红色背景。

02  核心业务概念与状态模型
2.1 Event / Alert / Incident
对象
定义
示例

Event
设备、算法或用户行为产生的原始事件。并不一定需要处置。
声学定位结果、AI 分类、温升、设备离线、参数修改

Alert
Event 命中告警规则后生成的“需要关注/处置”的对象。
Methane Leak HIGH；DTS hotspot MEDIUM

Incident
一个现实世界问题，可关联多个 Alert / 多个设备 / 多种传感器。
Transformer T03 abnormal condition，关联 Acoustic + Thermal + DGA

2.2 Alert 状态机
New  →  Acknowledged  →  Investigating  →  Resolved  →  Closed
  ↘       ↘              ↘
   Muted   Reassigned      Reopened → Investigating

Muted 是通知/显示策略，不等于 Resolved。静默期间事件仍然记录。
Reopened 用于已解决事件再次满足触发条件，需记录重新开启原因。
状态变更必须进入 Activity，并记录时间、操作者、前后状态。

14  事件聚合与 Incident 关联
14.1 重复触发聚合
同一设备 / 同一事件类型 / 指定时间窗口内的连续触发，默认聚合为一个 Alert 对象。
Methane Leak · Valve V104
First detected   14:01
Last detected    14:10
Duration         9m 18s
Occurrences      10
Concentration    18 → 32 ppm·m ↑

聚合依据必须可配置：assetId / eventType / detectionRegion / ruleId / timeWindow。
聚合后仍保留原始 Event 明细，可在 Timeline / Raw Events 中展开。

15  交互、响应式与可用性
15.1 Interaction Rules
动作
行为

Select alert
打开右侧 Drawer；保持当前滚动位置

Acknowledge
立即更新状态；写入 Activity；不关闭 Drawer

Assign
Popover 选择用户/组；成功后保留 Drawer

Resolve
要求 Resolution reason / optional note

Click KPI
转成筛选条件，不跳页

Click asset/device
新路由或新侧边详情，避免覆盖当前事件状态

15.2 Responsive
Viewport
规则

≥1600 px
Sidebar 232 / Filter 216 / Drawer 440；Content padding 32

1280–1599 px
默认规格；Drawer 400

1024–1279 px
Sidebar 默认折叠；Filter 以 overlay / toggle 打开；Drawer 360–400

<1024 px
不作为工业桌面主目标；允许降级为两层布局

15.3 Accessibility / Quality
所有颜色状态同时使用文字/图标，不依赖颜色单独表达 Severity。
Keyboard focus 必须清晰；focus ring 建议 2 px rgba(255,106,26,.35)。
按钮、列表行、Filter 具备可访问名称；Tooltip 不能承载唯一关键信息。
时间统一支持用户时区，并在详情中允许查看绝对时间。

18.2 必须通过的 UI 验收
☐  1440×900 下无横向溢出；Sidebar expanded + Filter + Drawer 同时开启仍可正常操作。
☐  Sidebar 在 232 px / 64 px 两种状态切换，动画 180–220 ms，折叠后 Tooltip 正常。
☐  所有主要颜色、间距、字号、圆角来自 Design Tokens；禁止散落 magic numbers。
☐  Alert Row 严重度不使用整行大面积红/橙色；Selected Row 使用轻橙背景。
☐  点击 Alert 不跳转全页，直接打开 Drawer；关闭后列表滚动位置保持。
☐  Acknowledge / Assign / Investigating / Resolve / Close 状态变化实时反映并记录 Activity。
☐  Evidence 根据 sensorType 切换组件；Acoustic / DTS / DAS / DGA 至少各有一个 demo renderer。
☐  重复 Event 可以在 UI 中显示 occurrenceCount、firstDetectedAt、lastDetectedAt、duration。
☐  KPI 点击可转换为 Filter；Saved View 可恢复主要筛选和视图模式。
☐  文本、图标和 Badge 在 100% 系统缩放下清晰，不存在 <11 px 关键文本。
