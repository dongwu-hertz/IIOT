## 一、怎么拿到这批截图

截的不是空壳：脚本会把你**真实**的数据库**复制**一份到一次性 profile，所以截图里是你的真设备
（2026-09-17 收盘时库里是 **3 台**：AE08、Acoustic Camera、SN-16 空气声呐）。

```powershell
# 先构建（改了源码之后必须）
node .\node_modules\electron-vite\bin\electron-vite.js build

# 出图：--with-data 复制真实库；截图落在 .demo-shots-real\
node scripts\demo-shot.cjs --with-data --out .demo-shots-real
```

三件必须说清楚的事：

1. **只读复制，不动原库。** 你的应用可能正在运行，脚本只 `copyFileSync` 出去（WAL 模式下连同
   `-wal` / `-shm` 一起复制，否则会拿到缺最近提交的旧快照）。
2. **副本里的账号被清空了。** 真实库里的管理员密码是你自己改过的，探针不知道也不该知道；
   而 `AuthService.ensureSeedAccount()` 每次启动都会在"用户表为空"时重建出厂管理员
   （`admin` / `Hz@123456`，首次登录强制改密）。清的是**副本**，设备和通道都留着。
3. **原库一个字节都没写。** 想确认可以比对文件时间戳。

### 病根：清单根本不是弹在你点的地方

上一版的相机选择器是一个**原生 `<select>`**，藏在整面墙末尾的一个 `1×1` 的隐藏盒子里
（`.visually-hidden`），点 `+` 的时候用 `showPicker()` 打开它。原生下拉贴在**它自己那个盒子
的边上**（浏览器行为，不是我们写的位置），而那个盒子在**页面左上区**。在你那台机器上量到：

| 量到什么 | 值 |
|---|---|
| 隐藏盒子（= 下拉的锚点） | 横 273、纵 97，`1×1` 像素 |
| 你点的那一格 | 横 834–1389、纵 148–460 |
| 两者相距 | **561 像素** |

所以你看到的像是"弹了一下／被盖住／没显示"。另外还有一条退化路径：`showPicker()` 需要**真实
的鼠标手势**，拿不到就抛异常、代码退回把焦点给那个被裁掉的 `1×1` 控件 —— 那种情况下屏幕上
**什么都不会发生**。

顺带把你看到的那行「请选择相机」解释清楚：它是那个下拉唯一的**占位文字**。你库里只有一台
相机，而总览页开机自动播放会先把那台相机放进一格 —— 于是空白格里"能选的相机"恰好是 **0** 台，
下拉里只剩那一行占位。

### 改了什么

- 选择器换成**自己画的浮层**（`CameraCellPicker.vue`，挂在窗口上、不随页面漂），位置由一个
  纯函数算：**贴在你点的那一格的下面**（4px），下面放不下就**翻到上面**，最后夹进窗口内。
- 空清单不再是一行占位文字，而是一句短状态词：**「没有可选的相机」**。
- 键盘可用：`+` 回车打开、↑/↓ 选、回车确定、Esc 收起（收起后焦点回到 `+`）；点旁边、滚动、
  改窗口大小都会收起。
- 「哪几台相机可选」还是原来那一份判断（已经在别的格子里的不再列出），一个字都没改。

## BB. 「认证失败…」这类内容收进右上角那颗告警图标（2026-09-18，业主口径）

> 你这一轮的原话：「认证失败，检测用户名和密码 这些告警内容，直接放在右上角的告警 ICON 内，
> 而不是在软件中进行顶部添加信息。要确保整体的布局不会因为告警等内容而改变。」
> 已经改掉。技术细节（含每一条"什么搬、什么不搬"的理由）在
> `docs/Ivms4200-UX-REFERENCE.md` **§15.47**。

### 它原来长什么样

`devices.error`（设备列表 / 通道表 / 状态刷新这一类**读**失败，认证失败就在其中）被画成**顶栏
下面一条浮动的横幅**，横跨整个窗口宽度。两个后果：它在**每一页**都在（所以你才在每一页都看到
那条「认证失败，请检查用户名与密码（AUTH_FAILED）」），而且它虽然不推内容，却**盖在内容上**。
总览页还另外画了同一个字段的第二份。

### 现在在哪

右上角那颗**告警图标**里。点开它，最上面那一段就是「**系统消息**」：

- 逐条列出（那句话 + **第一次出现**的时刻 + 一个「忽略」的 ×），右上角还有「全部清除」；
- 图标上多一个**小红点**表示"有系统消息"—— 图标上的**数字角标仍然只是待处理告警条数**
  （与面板里那份列表同源），两者不相加：一个数字配一份别的列表就是界面在说假话；
- 面板是浮层，所以这些内容的出现与消失**不动任何布局**（探针逐项量过：内容区顶边、页面顶边、
  页面高度、滚动位置、顶栏高度，打开前后完全一样）。

**什么搬了、什么没搬**（一句话：应用级的事实进图标，你刚点的那一下留在原地）：

| | 去哪 |
|---|---|
| 设备侧的**读**失败（列表 / 通道表 / 状态刷新，认证失败属于这一类） | 告警图标里的「系统消息」 |
| 增删改设备、保存设置、确认告警、导入导出…… 的失败 | **留在原地**（对话框 / 卡片 / 页面那一条），因为那是你刚点的那一下的结果 |
| 「本次结果被截断」「数据不完整」这类说明 | **留在原地**，它是这一页此刻的内容 |

同一个来源只留**一行**：它反复失败不会把面板刷成一片同样的字，时间也仍然停在第一次那一刻。

### 第 9 轮做完的一条（2026-09-18 第 10 批第 1 条：每次打开总览界面默认开启视频流）

**病根很具体，不是"判定写错了"**：自动起播的判定函数 `decideCameraAutoPlay()` 本身已经在
"设置开着 + 设备在线 + RTSP 不是已知坏的"时返回 `start`，也就是**不要求"相机已经在工作"**。
真正挡住这条要求的是它前面那道一次性守卫：

> `autoPlayAttempted` 那一位活在模块作用域里，清空时机是**一次应用启动**。

于是：第一次进总览 → 起播过 → **再进总览永远是「本次已经试过了」**，画面停着不动。
而"一次应用启动只试一次"这条守卫本身是有理由的（绝不进入重试循环），所以**不能整条删掉**。

**改法**：把清空时机从"一次进程"挪到"一次进页面"，并且**只清"试过了吗"**。

| 函数 | 清什么 | 什么时候调 |
|---|---|---|
| `resetAutoPlayAttempts()`（**新增**） | 只清 `autoPlayAttempted` | 进入**总览画面墙**与**实时监测相机页**的挂载钩子里 |
| `resetAutoPlayGuards()`（原有） | 清全部（含"手动停止"） | 只在测试里模拟"一次新的应用启动" |

三条推理，缺一条这个改法就不成立：

1. **一次停留里仍然只有一次尝试**：清的是"上一次进页面试过了吗"，所以失败不会自转重试
   （那个守卫的初衷保住了）；
2. **`manualStopped` 绝不清**：操作员按过「停止视频」的东西，不该因为他换了一次页面就自己回来。
   这是与 `resetAutoPlayGuards()` 的**全部区别**，也是这一位必须单独存在的原因；
3. **已经知道关着 RTSP 的相机不会被反复撞**：`rtspAvailability` 那一位在 store 里、按进程活着，
   所以"每次进页面"不会变成"每次去设备上撞一次"。

**同一个改法也用在实时监测的相机页**：第 20 条要的是"选中即自动播放"，而"一次进程一次尝试"
会让第二次进入这一页时画面停着不动。两页同一条口径。
> 这**解掉了上一轮留下的那处保留**（上一轮我写的是"手动停过/本进程试过的相机再选回来不会自动起播"）。
> 现在只剩一条约束：**手动停止优先**。

**双击进详情**（同一台设备的设备列表那一行第三轮就有双击了，这一轮把标记也接上）。

- **相机的浮层多一行「当前视频流」**（第 15 条）；声纹设备没有这一行（第 16 条只要基本信息）。
  那一行的文字复用相机页的 `cameraLiveUi.status*` —— 同一个故障在浮层和相机页徽标上
  必须是同一句话。
- **告警那一行与图上的颜色同源**：都用 `alarmFacts` 里那个"未确认条数"，所以红点与浮层
  不可能对不上；而"没读到"（`-1`）与"没有"（`0`）分开说。

**三条实现上的判断（都是我们定的，理由都写在代码里）**：

1. **浮层里不放 `<video>`**（这一条最要紧）。主进程对**一台相机只有一条会话，而一条会话
   只有一个观看者**（`CameraLiveSession` 的 `res.write` 对象）。悬停就去接管那条会话，
   会把**正在看这一路的人**的画面当场换掉 —— 一个鼠标划过就能踢掉别人的画面。
   所以这一行给的是**这一路视频流现在的状态**（播放中 / 未启动 / RTSP 未启用…），不是画面本身。
   > 也就是说：第 15 条的「显示…当前视频流」我们落成了「显示当前视频流**的状态**」。
   > 这是刻意的取舍，不是漏做；要改成"真出画面"的话，得先解决"一条会话一个观看者"这件事。
2. **位置用百分比算**（`x / 1280`、`y / 720`），不量盒子：标记坐标就在画布的逻辑坐标系里，
   而定比例那一层与画布**恰好同比例**。量 `getBoundingClientRect()` 要等一帧，
   缩放或滚动时会晚一拍。
3. **悬停与键盘焦点走同一套**（`@mouseenter`/`@focus`、`@mouseleave`/`@blur`）：
   标记本来就有 `tabindex="0"`，键盘走到它上面时浮层也该出来。
   浮层本身 `pointer-events: none` —— 它压在标记上，不这样鼠标会"离开"标记而闪。
