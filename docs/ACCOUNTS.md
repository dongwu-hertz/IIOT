# 应用账户、角色与密码找回

> 这是**软件自身**的账户体系。设备上的账号是另一回事：AE08 声纹盒与 FA371 声学相机
> 都只有唯一且不可改名的 `admin`，没有角色概念，相机的开放接口甚至不能改密码
> （`docs/reference/FA371-api-spec.md` §6）。所以"管理员 / 普通用户 + 忘记密码能找回"
> 只能由本软件实现。

---

## 1. 两种角色

| | 管理员 `admin` | 普通用户 `operator` |
|---|---|---|
| 查看总览 / 告警 / 录音 / 趋势 / 实时监测 | ✅ | ✅ |
| 协议实验室（只读诊断） | ✅ | ✅ |
| 添加 / 编辑 / 删除设备 | ✅ | ❌ |
| 修改设备配置（通道、采样率、网络、时间、RS485、Modbus、Push、名称） | ✅ | ❌ |
| 维护（重启、恢复出厂、固件升级） | ✅ | ❌ |
| 账户管理（创建 / 删除 / 重置密码 / 改角色） | ✅ | ❌ |

出厂只有一个账户：`admin` / `Hz@123456`，且**首次登录必须改掉**。

## 2. 密码是怎么存的

`scrypt`（`node:crypto`，无新依赖），每个密码独立随机盐，参数写进哈希串本身：

```
scrypt$32768$8$1$<saltBase64>$<hashBase64>
```

- **不是**设备那套 `md5(明文 + 'lfxs')`。那是固件强制的协议怪癖，仓库里明确注明它不是安全措施
  （`auth-strategy.ts`）。本软件自己的账户没有理由用它。
- 参数自描述，所以将来提高成本不会让老密码失效。
- 验证用 `timingSafeEqual`；格式损坏的哈希一律当"验证失败"，绝不抛异常。
- 用户名不区分大小写（`COLLATE NOCASE`），避免出现两个 `Admin`。
- 用户不存在时也会走一次完整的 scrypt 计算（对固定假哈希验证），
  否则登录响应时间就能枚举出哪些用户名存在。

**成本参数的坑（已修）**：`node:crypto` 的 `maxmem` 默认 32 MiB，而
`128 × N × r = 128 × 32768 × 8` 恰好是 32 MiB。判定是严格大于，于是整个 auth 模块在
`import` 时抛 `ERR_CRYPTO_INVALID_SCRYPT_PARAMS`。现在显式传入内存预算。

## 3. 防爆破

同一用户名连续 5 次失败 → 锁定 60 秒（内存中，进程重启即清空）。
锁定期间**即使密码正确也拒绝** —— 否则锁定只对"猜得很差的人"有效。
成功登录后计数清零；找回密码也会清空锁定，因为被锁在门外的管理员正是找回功能的目标用户。

## 4. 超级密码：为什么不是"一个固定口令"

有两种做法：

- **(a) 一个固定的出厂超级密码**，写进文档、所有安装相同。实现简单，也是同类产品的常见做法。
- **(b) 每台机器一个找回码**，由出厂密钥与本机安装标识派生。

选了 (b)。理由：一个写进手册的"万能口令"一旦泄露，**所有**部署同时失守，
包括那些从来不需要找回的；而 (b) 让同一句话的业务流程（"把登录页上的安装标识报给厂家，
厂家念一串码给你"）保留下来，同时泄露的码在别的机器上毫无用处。

```
超级密码 = group(HMAC-SHA256(出厂密钥, 规范化后的安装标识)) 取前 16 位
```

- 安装标识由本机首次启动时生成并持久化（`app_meta.install.id`），显示在登录页，
  **它是标识符，不是秘密**。
- 超级密码**不存盘**，数据库里只有安装标识 —— 拷走数据库也拿不到找回码。
- 字母表去掉易混字符（`ACDEFGHJKLMNPQRTUVWXY34679`），因为它要被电话念出来。
- 比较时忽略大小写、空格与连字符，因为它是人照着屏幕或电话敲进去的。

签发与校验：

```bash
node scripts/recovery-code.cjs AB12-CD34-EF56-7890          # 签发
node scripts/recovery-code.cjs --verify AB12-CD34-EF56-7890 D49H-PJ73-YRN3-TKHD
```

**这个脚本刻意重复了一份派生逻辑**：支持人员的机器上只有 Node，没法 import 应用的
TypeScript。重复实现意味着漂移风险，而不一致的后果很糟糕（厂家念的码用户输进去说不对，
双方都不知道谁错了）。所以 `tests/recovery-code.test.ts` 会**真的执行这个脚本**，
与应用里的 `recoveryCodeFor` 逐 id 比对 —— 这个测试第一次运行就抓到了一个真实缺陷：
`recoveryCodeFor` 当时只做了 `trim().toUpperCase()`，没有去掉连字符，
于是带连字符的标识会派生出完全不同的码。

**这条路不是万能的**：出厂密钥在二进制里，拿到二进制又拿到安装标识的人可以自己算出码。
它防的是"一个码泄露=全网失守"、"从数据库读出码"、"技术员记住万能口令反复用"。

## 5. 会话在主进程，不在渲染进程

登录状态由 `AuthService` 持有。渲染层也拿一份只是为了渲染界面
（显示用户名、隐藏管理员按钮）；**每一个需要权限的 IPC handler 都在主进程重新判定**，
因为渲染层说自己是管理员只是"声明"，不是"证明"。

| 受保护（需管理员） | 不受保护 |
|---|---|
| 账户管理、设备增删改、全部设备配置写入、维护（重启/恢复出厂/升级） | 所有读取：设备列表、告警查询、录音查询、配置读取、协议实验室 |

读取不设防是**有意的**，不是遗漏：渲染层是本仓库自己的产物，从磁盘加载、严格 CSP、无远程内容，
且在会话建立前根本不挂载外壳；而给约 40 个读 handler 各加一道守卫，意味着 40 个可能忘记的地方，
**忘记一个写守卫是真提权，忘记一个读守卫没人看得出来**。把检查集中在真正会改变硬件行为的操作上，
反而让已有的检查是可复核的。

诚实地说清局限：**恶意渲染层仍然可以读**。一旦本软件增加远程访问模式，读取也必须加守卫 ——
会话已经在主进程里，那个改动是增量式的。

## 6. 审计与可追溯

- 登录成功/失败、账户创建/删除、角色变更、密码修改与重置 **全部写 app 日志**。
- 破坏性操作（重启、恢复出厂、固件上传）记录 `by=<用户名>`；
  共享控制台上没有这一行，事后就查不出"14:02 是谁重启了设备"。

## 7. 为什么"修改密码"没有设备端接口

设备端只有 Web UI 能改密码，开放接口没有这个能力；本软件的账户密码与设备凭据是两套东西，
互不影响。设备凭据存在操作系统凭据库中（DPAPI），与应用账户密码无关。

## 8. 如果所有人都忘了密码

```bash
# 1. 在登录页点「忘记密码」，抄下安装标识
# 2. 厂家签发
node scripts/recovery-code.cjs <安装标识>
# 3. 用该码重置任一已存在账户的密码（只能重置，不能登录、不能建号、不能改角色）
```

## 9. 数据库层面

schema 4 新增：

```sql
users(id, username UNIQUE COLLATE NOCASE, display_name, role CHECK(role IN ('admin','operator')),
      password_hash, must_change_password, last_login_at, created_at, updated_at)
app_meta(key PRIMARY KEY, value)   -- 目前只存 install.id
```

`role` 的 CHECK 与 `shared/domain/auth.ts` 的联合类型是有意的重复：
数据库是最后一道防线，一个拼错的角色必须在写入时就报错，而不是产生一个权限判定无法归类的账户。
读取时若遇到未知角色，一律降级为 `operator`（最小权限），绝不因比较巧合而变成管理员。

## 10. 加了登录之后，所有无人值守验证都要先登录

外壳挂在会话之后，**未登录时不会挂载外壳，也就不会读取任何设备**。这条性质让所有
headless 验证脚本在加登录的那一刻全部失效（外壳不存在 → "vue 未挂载"、"没有导航文案"、
`devices.add` 返回 FORBIDDEN）。因此下列脚本都先走一遍真实的两步登录（出厂密码 → 强制改密），
用的都是它们自己的一次性 profile：

| 脚本 | 做法 |
|---|---|
| `src/main/index.ts` 的 smoke 探针 | 在 bridge 探针里先 `auth.login` + `auth.changePassword`；会话在**主进程**，因此后面的语言探针反复 reload 也不会掉线 |
| `scripts/verify-packaged.cjs` | 断言登录步骤到达 `changed`，并新增一条断言：**登录前 `mountedBeforeSignIn === false`** |
| `scripts/demo-shot.cjs` | 截图前先登录，否则截到的是登录页 |
| `scripts/verify-fa371.cjs` | 设备调用前先登录，否则全部 FORBIDDEN |

「登录前不挂载外壳」这条被写成了 `verify:packaged` 的断言，因为它的回归**没有任何可见症状**：
外壳提前挂载，只是意味着未登录时也读了设备，界面上完全看不出来。
